# 03 — Feature Catalog

> Stable document. **IDs are permanent: never reused, never renumbered.** To retire a feature, mark it `Status: DEPRECATED (reason, date)` — do not delete. To add one, append a new ID at the end of its module block using the next unused number, add it to docs/04 **in the same change**, then build it.

**Acceptance criteria (AC)** are written so an agent can verify them itself with a test or a command. "Done" means all ACs pass **and** `make check` is green (docs/11 §4).

Layer tags: `[D]` domain, `[A]` application, `[I]` infrastructure, `[P]` presentation, `[W]` web frontend.
Priority: **M** must-have for submission, **S** should-have, **C** could-have (stretch).

Test image sources: "synthetic" = generated by F-100; "real" = human-supplied in `data/samples` (tests marked `needs_real_samples`, skipped if absent).

## Module QA — Test infrastructure & guardrails

### F-100 — Synthetic map generator [I+tests] (M)
Generate test images with known ground truth: a smooth analytic field (e.g. sum of Gaussians + latitude gradient, with a NaN "land" mask), rendered through any matplotlib colormap into an equirectangular map with a drawn colorbar (horizontal or vertical) and optional border, title text and white margin. Returns `(png_bytes, truth_field, legend, colorbar_box, map_box)`.
- AC1: `generate_map(cmap="viridis", seed=1)` returns identical bytes on repeated calls.
- AC2: works for ≥ 8 colormaps incl. one diverging (`RdBu_r`) and one rainbow (`turbo`).
- AC3: truth NaN mask matches land region; colorbar box and map box are inside the image and non-overlapping.

### F-101 — Ground-truth manifest loader & validator [I] (M)
Load `data/samples/*/meta.json` into `SampleMeta` (schema docs/12 §3); validate fields, boxes inside image, vmin<vmax, id pattern.
- AC1: directories starting with `_` (e.g. `_TEMPLATE`) are ignored; a valid sample loads; `list()` returns only samples with `in_gallery=true`, while `get(id)` also returns hidden ones.
- AC2: each of 6 invalid meta files (missing field, bad box, vmin≥vmax, bad id, missing image, bad category) raises `InvalidLegendError`/`InvalidImageError` with a message naming the file and field.
- AC3: listing with zero real samples returns an empty list, not an error.

### F-102 — Determinism & golden tests [tests] (M)
- AC1: for every synthetic fixture, two runs of the full pipeline give byte-identical Score JSON and WAV.
- AC2: a golden Score JSON for one fixed synthetic input is committed in `tests/golden/`; test fails on any diff; regenerating requires `MAPPING_VERSION` bump (test asserts the golden's `mapping_version` equals the constant).

### F-103 — Evaluation report script [tests/scripts] (S)
`python -m scripts.evaluate` runs F-100 fixtures (+ real samples when present) and writes `docs/EVAL-REPORT.md` with tables: inversion error, quality badge, round-trip r, legend-pitch r.
- AC1: command exits 0 and writes the file; numbers reproducible across runs.
- AC2: report lists per-colormap RMSE as % of range and the pass/fail thresholds from docs/05 §9.

### F-104 — Architecture guardrails [config/tests] (M) — DONE in Phase 0
import-linter contracts, docs-in-sync test, frontend layering test. **Never weaken, delete or skip these** (docs/11).
- AC: `make arch` passes on a clean tree and fails when a violation is introduced (proved in docs/10 §6).

### F-105 — Submission pack [docs] (S)
`docs/SUBMISSION/` with: one-page project summary, methodology (mapping table rendered), AI-tool-use disclosure, data credits, 3-minute demo script, screenshots list.
- AC: every claim of a number in the summary links to a line in `EVAL-REPORT.md`; credits include every bundled sample's `credit`.

### F-106 — CI workflow [config] (S) — DONE in Phase 0
`.github/workflows/ci.yml` runs `make check`.

## Module IMG — Image ingestion & data recovery (docs/05)

### F-001 — Upload validation & decoding [I] (M)
Implements `ImageDecoder`. Accept PNG, JPEG, WebP, GIF (first frame). Reject others, > 20 MB, > 8000 px/side, or undecodable bytes.
- AC1: valid PNG/JPEG/WebP/GIF fixtures decode to `(H,W,3)` uint8.
- AC2: a text file renamed `.png`, a truncated PNG, and a 9000×10 PNG each raise `InvalidImageError` (distinct messages).
- AC3: `content_hash` equals `hashlib.sha256(original_bytes).hexdigest()`.

### F-002 — Image normalisation [I] (M)
Apply EXIF orientation; flatten alpha onto white; convert to sRGB RGB; produce a working copy with max side ≤ `Settings.working_max_dimension` using **area** interpolation. Keep `original_width/height`.
- AC1: RGBA with transparent corners → corners white.
- AC2: EXIF-rotated JPEG fixture comes out upright.
- AC3: boxes given in original coordinates are mapped to working coordinates by one tested helper (`scale_box`), round-trip error ≤ 1 px.

### F-003 — Colormap preset catalog [I] (M)
Implements `ColormapCatalog` using matplotlib: at least `viridis, plasma, inferno, magma, cividis, turbo, jet, Blues, Greens, YlGnBu, YlOrRd, Reds, RdBu_r, RdYlBu_r, coolwarm, BrBG, PuOr, seismic, gray`. Each has a `ColormapKind`.
- AC1: `lut("viridis", 256)` has shape (256,3) Lab, values ascending 0..1.
- AC2: unknown name raises `InvalidLegendError`.
- AC3: `names()` is sorted and stable.

### F-005 — Manual region specification [A] (M)
Use case `recover_field` accepts `map_box` and `colorbar_box` (original-image px). If `map_box` is omitted, the map region = whole image minus colorbar box (and minus a 1 % border).
- AC1: boxes outside the image → `InvalidLegendError`.
- AC2: overlap of map and colorbar boxes > 0 → `InvalidLegendError`.

### F-006 — Colorbar → LUT extraction [I] (M)
From `colorbar_box` + orientation: trim outer 2 px border and any end-cap pixels (rows/cols that differ from the interior by > 20 ΔE at the very ends, max 3 % of length); take the **median** across thickness at each position; resample to ≤ 512 entries; return `ColorLUT` ordered vmin→vmax honouring `low_at_start`.
- AC1: on synthetic horizontal and vertical bars of 8 colormaps, extracted LUT vs. matplotlib's colormap has mean ΔE ≤ 2.0.
- AC2: `low_at_start=False` reverses order (test).
- AC3: a bar with a 1-px black outline gives the same LUT (±ΔE 1) as without.

### F-007 — Legend metadata [A] (M)
Validate/construct `LegendSpec` from user input (vmin, vmax, units, label, kind, category, center, orientation, low_at_start).
- AC1: vmin ≥ vmax, center outside range, unknown category, log scale with vmin ≤ 0 → `InvalidLegendError`.
- AC2: `kind=DIVERGING` without center → center = midpoint, and the response says so in `warnings`.

### F-008 — Colour → value inversion [I] (M)
Convert map pixels to Lab, query a `cKDTree` over the LUT, interpolate value between the two nearest LUT neighbours along the bar (sub-LUT-step precision, doc 05 §5). Pixels whose nearest distance > `max_delta_e` (default 12) → NaN.
- AC1: synthetic fields recovered with RMSE ≤ 2 % of range for sequential maps and ≤ 3 % for `turbo`/`jet` (doc 05 §9 table).
- AC2: result is deterministic.
- AC3: 2048×1024 image inverts in ≤ 3 s on the dev machine (log, soft check).

### F-009 — Non-data masking [I] (M)
Mark as NaN pixels that are not data: distance-to-LUT above threshold, plus **text/graticule suppression** (thin dark/white line pixels removed by morphological opening mask, doc 05 §6), plus uniform ocean/land background colours detected as a dominant non-LUT cluster covering > 5 % of the map.
- AC1: synthetic land mask recovered with IoU ≥ 0.95.
- AC2: synthetic black graticule lines (1 px) do not appear as extreme values (no value outside [vmin−1 %, vmax+1 %]).

### F-010 — Geo-extent & unsupported-projection warning [A] (M)
Attach `GeoExtent` (default global); if `projection != "equirectangular"` or the map aspect ratio is far from the extent's (ratio mismatch > 15 %), add warning `"projection_unverified"` and lower confidence.
- AC1: 2:1 image with global extent → no warning; 1:1 image with global extent → warning.

### F-011 — Recovery quality report [A] (M)
Compute `RecoveryQuality` (doc 05 §8).
- AC1: perfect synthetic recovery → confidence ≥ 0.9; map recovered with wrong preset → confidence < 0.5 and warning `"high_color_distance"`.
- AC2: confidence formula implemented exactly as documented; unit-tested at the boundaries.

### F-013 — Luminance fallback [I] (S)
If neither colorbar nor preset is given, use CIE L* mapped linearly to [vmin, vmax]; mode `LUMINANCE_FALLBACK`; confidence capped at 0.3; warning `"not_data_faithful"`.
- AC1: grayscale gradient recovers monotonic values.
- AC2: warning is present in ScalarField.quality and appears in the API response and description text.

### F-004 — Colorbar auto-detection [I] (S)
Propose a `PixelBox` + orientation for the colorbar (doc 05 §4): find long thin high-colour-variety strips near image edges using gradient continuity; return top-3 candidates with scores. Result is a *suggestion*; UI shows it for confirmation.
- AC1: on ≥ 8 synthetic layouts (colorbar bottom/right/inside margin; with/without outline; with tick labels) the true box is the top candidate with IoU ≥ 0.8 in ≥ 7 of 8.
- AC2: on blank/noise images returns an empty list, not an error.
- AC3: on real samples (marked `needs_real_samples`) report the hit-rate in EVAL-REPORT; no hard threshold.

### F-012 — OCR legend assist [I] (C)
Optional (`pytesseract` extra). Reads numbers/units near the colorbar to propose vmin/vmax/units. Always only a suggestion; absent Tesseract ⇒ feature reports "unavailable".
- AC1: with Tesseract missing, returns `None` without raising.
- AC2: on synthetic bars with tick labels, extracts min and max within 1 % in ≥ 6/8 cases.

## Module SON — Sonification engine (docs/06)

### F-020 — Field resampling to grid [D] (M)
Resample `ScalarField` to `(n_bands × n_cols)` by nan-aware **mean** in each cell, plus per-cell coverage (fraction of non-NaN).
- AC1: constant field → constant grid; coverage 1.
- AC2: field with half NaN → coverage 0.5 and mean unaffected by NaN.
- AC3: property test (hypothesis): grid mean ∈ [field min, field max].

### F-021 — Normalisation & centre handling [D] (M)
Normalise value → `u ∈ [0,1]` per docs/06 §3: sequential linear; diverging piecewise-linear with `effective_center` ↦ 0.5.
- AC1: vmin→0, vmax→1, centre→0.5 (diverging), monotonic non-decreasing.
- AC2: values outside [vmin,vmax] clamp.
- AC3: `scale=LOG` normalises in log10 space (u of the geometric mean of vmin,vmax = 0.5).

### F-022 — Value → pitch (scale quantisation) [D] (M)
`pitch(u, skin)` per docs/06 §4: index into the skin's pitch set over `n_octaves`, rounded to the nearest degree; returns fractional MIDI (cents-aware).
- AC1: monotonic non-decreasing in `u` for every skin.
- AC2: `u=0` → lowest note; `u=1` → highest note; diverging centre → the tonic of the middle octave.
- AC3: same `u` gives same pitch regardless of band (P2).

### F-023 — Time/sweep mapping [D] (M)
Column `c` ↦ `t_beat = c * 1.0`; the playhead sweeps west→east. `total_beats = n_cols`.
- AC: for n_cols=48 the last note starts at beat ≤ 47 and `total_beats == 48`.

### F-024 — Latitude band → voice & pan [D] (M)
5 equal-latitude bands (north→south): voice ids `band0..band4`; pans exactly as the docs/06 §5 table (`-0.6,-0.3,0,0.3,0.6`, north = left).
- AC: voices constructed deterministically; pans exactly as the table; instrument from skin.

### F-025 — Local variability → rhythm density & roughness [D] (M)
Gradient magnitude per grid cell (nan-aware Sobel on the grid) → density class 1/2/4 notes per beat by percentile thresholds; roughness 0..1 stored in `NoteEvent.roughness` (docs/06 §7).
- AC1: a flat field gives density 1 everywhere; a checkerboard gives 4 at edges.
- AC2: thresholds are the documented percentiles, computed over valid cells only.

### F-026 — Global variability → tempo [D] (M)
`bpm = 72 + 48 * s` where `s` = clamp(std of valid `u` / 0.30, 0, 1).
- AC: constant field → 72 bpm; maximal-variance field → 120; monotone in std (property test).

### F-027 — Extremes accents [D] (M)
Cells whose |u−0.5| rank is in the top 5 % of valid cells get `accent=True` and velocity +0.25 (cap 1.0), and get a bell-voice doubling one octave up.
- AC1: on a field with a single hot spot, exactly the hot-spot cells are accented.
- AC2: accent count ≤ ceil(5 % × valid cells) + ties.

### F-028 — Silence for masked data [D] (M)
Cells with coverage < 0.25 produce **no note** (a rest).
- AC1: all-NaN field → Score with zero notes (plus drone) and a `warnings` provenance entry.
- AC2: every note has finite `value`.

### F-029 — Category → instrument family [D] (M)
Skin's `instrument_map` selects family ids per `VariableCategory` (docs/06 §6). Unknown → `generic`.
- AC: every `VariableCategory` resolves for every shipped skin (parametrised test).

### F-030 — Drone / harmonic bed [D] (M)
A sustained tonic + fifth drone for the whole track (`drone_midi`); its brightness hint = mean `u` (provenance `drone_brightness`).
- AC: drone pitches = tonic and tonic+7 semitones of the skin (or skin's "fifth" degree), independent of data except brightness.

### F-031 — Deterministic seeding & ornaments [D] (M)
`seed = int(sha256(source_hash + params_json + MAPPING_VERSION)[:8], 16)`. A seeded `numpy.random.Generator` is the only RNG. Ornaments (grace notes on accented cells) use it.
- AC1: same inputs ⇒ identical Score; different `source_hash` ⇒ different seed.
- AC2: grep-test: no `random.`/`time.`/`datetime.now` in domain.

### F-032 — Score assembly [A] (M)
Use case `sonify(field, params) -> Score` combines F-020…F-031; fills `provenance` (mapping_version, skin_id, recovery mode, confidence, warnings).
- AC1: Score JSON validates against docs/07 §2 schema.
- AC2: notes are sorted by `(t_beat, voice_id, pitch)`; no NaN anywhere.
- AC3: every note `value` is within [vmin,vmax].

### F-033 — Mapping manifest [A] (M)
`describe_mapping()` returns a JSON document of the fixed mapping (docs/06 tables, constants, version) — used by the UI "How to listen" panel and the submission pack.
- AC: contains `mapping_version` and every row of the docs/06 §2 table; a test fails if the table in docs/06 and manifest keys diverge (key list asserted).

### F-034 — Audio legend sweep [A] (M)
`legend_score(legend, skin) -> Score`: 32 notes stepping u=0→1 (one per beat at 96 bpm), one voice, instrument of the category; for diverging maps, a tonic marker (bell) at the centre.
- AC1: notes' pitches strictly ascending where the scale allows (non-decreasing, ≥ 12 distinct pitches).
- AC2: `value` of first/last note = vmin/vmax.

### F-035 — Score round-trip decoder [A] (M)
`decode_score(score) -> grid of values` (inverse of the pitch map); `fidelity_round_trip(field, score) -> r`.
- AC1: on synthetic fixtures r ≥ 0.95 for the neutral skin.
- AC2: decoder uses only Score data (not the field).

### F-036 — Text description generator [A] (M)
Plain-English description: variable, units, range, where highs/lows are (by band and longitudinal third), % masked, quality caveats, and a one-line "how to listen".
- AC1: deterministic; ≤ 120 words; contains units and min/max.
- AC2: includes the literal phrase "approximate" when quality.confidence < 0.7 and "not data-faithful" for luminance fallback.

## Module AUD — Rendering & export (doc 07)

### F-040 — NumPy synth voices [I] (M)
Instrument families: `pad`, `pluck`, `bell`, `flute`, `strings`, `sub`, `texture` (filtered noise), `percussion` (for Sri Lankan skin later). ADSR, vibrato/glide, `roughness` → filter/detune. Fractional MIDI → frequency; honours `glide_to_midi`.
- AC1: rendering a single A4 note → spectral peak within 5 cents of 440 Hz (FFT test).
- AC2: no clipping; no NaN/inf.
- AC3: all families render a note ≥ 0.5 s without error (parametrised).

### F-041 — Mixer, pan, limiter [I] (M)
Equal-power pan; sum voices; soft limiter to −1 dBFS; fade-in 50 ms/out 500 ms.
- AC1: peak ≤ 0.89 (−1 dBFS) for a dense 5-voice score.
- AC2: a hard-left voice has right-channel RMS ≤ 1 % of left.

### F-042 — WAV writer [I] (M)
Implements `AudioRenderer.render_wav` (44.1 kHz, 16-bit stereo via stdlib `wave`).
- AC1: valid header; duration = `total_beats*60/bpm` + tail (≤ 2 s) ± 50 ms.
- AC2: byte-identical across runs (F-102).

### F-043 — MIDI export [I] (S)
Implements `MidiExporter` with `mido`: one track per voice, tempo meta, microtones via pitch-bend (±2 semitone range).
- AC1: re-reading the file gives the same note count and tempo.
- AC2: a note at 60.5 produces note 60 + pitch-bend ≈ +50 cents.

### F-044 — MP3 export (optional) [I] (C)
If `ffmpeg` is on PATH, convert WAV → MP3 with fixed args; else the endpoint reports unavailable.
- AC: absent ffmpeg → graceful `501`-style problem response, no crash.

### F-045 — Render cache [I] (S)
Key = sha256(Score JSON + renderer version). Stored in `data/cache`.
- AC1: second render is a cache hit (test via spy/counter).
- AC2: cache never serves a different `mapping_version`.

### F-046 — FluidSynth adapter (stretch) [I] (C)
Optional alternative renderer behind the same port, only if `fluidsynth` + a CC0/team SoundFont exist. Not required for any phase.

### F-047 — Audio-level pitch check [I+tests] (M)
YIN pitch tracker (NumPy) on the rendered **legend sweep** (monophonic): detected pitch per note vs. expected.
- AC1: all notes within 20 cents.
- AC2: Pearson r between detected pitch and legend value ≥ 0.98; result stored in `FidelityReport.audio_legend_r`.

## Module SKN — Skins (doc 08)

### F-050 — Skin registry [D] (M)
`get_skin(id)`, `list_skins()`; `Skin` is data only.
- AC: unknown id → `NotFoundError`; every skin's `scale_cents[0] == 0`, ascending, < 1200.

### F-051 — Neutral skin [D] (M)
Major pentatonic (0,200,400,700,900) across 2 octaves from C3 (N = 11 pitches, doc 08 §2); instruments: temperature→`strings`, precipitation→`pluck`, vegetation→`flute`, ice→`bell`, aerosol→`texture`, ocean→`pad`, generic→`pad`.
- AC: passes F-022/F-029 tests.

### F-052 — Hindustani raga skin [D+I] (S)
Rule-based raga skin per docs/08 §3: aroha/avaroha-aware scale, pakad phrase templates for ornaments, meend glides via `glide_to_midi`. Variable-to-raga narrative table (rain → Malhar family; heat → Deepak; etc.). **Note sets must be validated by the team musician before this feature is marked done** (human step in docs/08 §5).
- AC1: the skin's scale equals the note set in the docs/08 §3 table (provisional flag set until the musician validates).
- AC2: invariance test F-054 passes.
- AC3: with `glide_descending`, every descending step between consecutive columns in the same band has `glide_to_midi` set (test).

### F-053 — Sri Lankan skin [D+I] (S)
Per docs/08 §4: scale choice (validated by the team), `percussion` voice playing geta-beraya/rabana-style patterns from `rhythm_patterns` locked to the density classes, flute (`flute`) lead; optional team-recorded samples if present in `data/audio/`.
- AC1: invariance test F-054 passes.
- AC2: rhythm pattern data lives in the skin (data), not in code branches.

### F-054 — Skin invariance test [tests] (M)
For every skin and 5 synthetic fields: (a) the sequence of values sorted by `u` maps to non-decreasing pitch; (b) note onsets/velocities/accents/voices/pans are **identical** across skins (only pitch values and instrument ids may differ).
- AC: test exists, parametrised over `list_skins()`, passes.

### F-055 — Skin selection in API/UI [P+W] (S)
Skin chosen per request; response includes skin metadata (name, scale description).
- AC: sonify endpoint accepts `skin`; unknown → 404-style problem response.

## Module TIME — Animation / time mode (Phase 9, stretch)

### F-090 — Frame extraction [I] (C)
GIF/APNG frames via Pillow; MP4/WebM via ffmpeg if present; ≤ 24 frames sampled evenly.
- AC1: Extract frames from animated GIF and APNG via Pillow; when frame count > 24, sample exactly 24 frames evenly spaced across the sequence.
- AC2: When input is a single frame (static image), return a sequence containing that single DecodedImage without error.
- AC3: When input is MP4 or WebM video bytes, extract up to 24 evenly sampled frames if ffmpeg is available; if ffmpeg is missing, raise InvalidImageError with an informative error message.
- AC4: Unrecognized or corrupt inputs raise InvalidImageError.

### F-091 — Per-frame phrases [A] (C)
Each frame → recovered field (same legend) → Score phrase; phrases concatenated with a 1-beat rest.
- AC1: Each extracted frame is recovered with the same legend and bounding boxes/preset into a ScalarField.
- AC2: Each frame's ScalarField is sonified into a Score phrase with phrase beats equal to `score.total_beats`.
- AC3: Phrases are concatenated sequentially with exactly a 1-beat rest between consecutive phrases (phrase k starts at beat `k * (phrase_beats + 1.0)`).
- AC4: Total beats of the concatenated Score equals `F * phrase_beats + (F - 1) * 1.0` where F is the number of frames.

### F-092 — Inter-frame change → harmonic tension [D] (C)
Mean absolute change between consecutive fields → drone adds a second/tritone-ish colour interval (skin-defined "tension degree") scaled by change.
- AC1: Inter-frame change is measured as the mean absolute difference of normalized scalar values `u` across consecutive valid fields.
- AC2: When inter-frame change is 0.0 (identical frames or single frame), drone consists of tonic and fifth without tension pitch.
- AC3: When inter-frame change > 0, drone adds a tension interval pitch determined by the skin's tension degree (e.g. second or tritone) scaled by the inter-frame change.
- AC4: Inter-frame change metric and tension pitch are recorded in the Score's provenance metadata.

- AC1: Pure time-mode function computes active frame index and phrase beat offset from current audio beat and phrase duration (node-tested).
- AC2: Frame strip container renders frame indicators/thumbnails with accessible ARIA semantics (`role="region"`, `aria-label`, `aria-current="true"` on active frame).
